# dsh-pocket 三通道独立管理改造方案

- 基线：upstream `shaobeichen/dsh-pocket` v2.10.3（`eb25503`）
- 状态：PR1 / PR2 已实现并经真机页面验收（2026-09-03），代码在 `feat/per-device-credentials` 分支

## 背景

插件目前提供三种外部访问方式：局域网直连（LAN）、Cloudflare 快速隧道（随机域名 Quick Tunnel）、Cloudflare 命名隧道（固定域名 Named Tunnel）。Quick 与 Named 二选一，共同构成"公网入口"。

当前实现把所有认证和安全防护混在一起：

- Quick 和 Named 共用同一个公网 PIN；
- 认证判定、限速、Cookie 均按"局域网/公网"两类组织，而不是按通道组织；
- 无法对某条通道单独配置认证方式、单独启停、单独撤销凭据。

上游 v2.10.2 / v2.10.3 已针对 Issue #90 落地了一批不改交互形态的安全修复（`?token=` 与 WebSocket 限速旁路、CSPRNG 生成 PIN、Host 头伪造收紧、CLI 默认认证），但通道拆分与设备认证尚未开始。

## 上游维护者的考量（Issue #90）

- 维护者明确表示：为了安全而砍掉必备的功能（局域网、Quick Tunnel、CLI）不合适；安全改进应在保留现有入口形态的前提下进行。
- 已落地的修复刻意不改任何交互形态，纯增强。
- 维护者认可后续方向：每设备凭据＋设备管理（撤销/命名/最后活跃时间）；本机批准仅用于初始配对。
- 维护者在 Issue #90 中建议的 PR 顺序：① 每设备凭据＋设备管理（保留现有入口形态）→ ② 一次性 `?token=` → ③ 一键作废/重置入口 → ④ 可选的固定域名＋本机批准强化模式 → ⑤ 风险文档。

## 我的考量

- 三个通道的使用场景不同：LAN 求方便，Quick 求临时，Named 求长期稳定。认证强度应随场景分级，而不是一套认证管所有入口。
- 把三个通道拆开、独立管理：每条通道可以单独启用、单独设置认证方式、单独撤销凭据，互不影响。
- LAN 和 Quick 保持"电脑设置一个共享密码、所有访问者共用"的方式：设备认证在 IP 变化（LAN）或随机域名变化（Quick）下体验不稳定，共享密码简单直接。
- Named Tunnel 是固定域名，浏览器 Cookie 可以长期保留，适合最严格的设备认证：首次配对由电脑批准，后续同一设备输入自己的设备密码即可，在家在外都可用，无需每次扫码。
- Named Tunnel 作为长期使用的首选推荐通道。

## 目标形态：三个通道拆开，独立管理

1. 局域网 LAN
- 地址：电脑局域网 IP；
- **默认关闭**：插件安装后不开启，必须手动开启至少一次（开启时必读安全声明）；开关状态跨 DSH 重启保持；
- 电脑端生成或设置一个 LAN 共享密码；
- 所有访问者使用同一个密码，并支持一键生成新的随机密码（立即生效）；
- 可开启免密，但需要显示高风险提示；
- 支持手动输入密码，或通过二维码携带 `?token=LAN密码` 完成同一种密码认证（一次性，认证通过后 URL 的 `?token=LAN密码` 消失）；
- 认证后保存会话 Cookie（10分钟无活动，再次访问需要重新输入密码）；
- 独立于两个公网通道；
- 不采用设备认证：浏览器无法获取可靠的设备网卡等硬件标识，而且局域网 IP 变化后，浏览器不会向新地址发送原地址下保存的设备 Cookie，设备认证体验不稳定。

2. 随机域名 Quick Tunnel
- 每次启动获得一个随机的 `trycloudflare.com` 域名；
- Tunnel 停止、断线或重启后，原域名失效；再次启动会获得新域名；
- 电脑端每次启动默认随机生成并轮换一个 Quick 共享密码，也允许一键生成新密码或用户自定义密码（设置自定义密码后随机生成的密码失效，自定义密码不会被覆盖）；
- 所有访问者使用同一个密码；
- 支持手动输入密码，或通过二维码携带 `?token=Quick密码` 完成同一种密码认证（一次性，和 LAN 相同）；
- 认证后保存会话 Cookie（10分钟无活动，再次访问需要重新输入密码）；
- 与 Named Tunnel 二选一；
- 不采用设备认证：浏览器 Cookie 按域名保存，Quick Tunnel 更换随机域名后，新域名无法使用旧域名下保存的设备 Cookie。

3. 固定域名 Named Tunnel
- 使用用户自己的固定域名和 Cloudflare Tunnel Token；
- 不使用 LAN 或 Quick 的共享密码；
- 作为长期使用的首选推荐通道，可以附带 Cloudflare Tunnel Token 的获取与配置教程；
- 与 Quick Tunnel 二选一。

首次使用：
- 注册 Cloudflare 并获取 Tunnel Token；
- 电脑完成固定域名配置。

添加设备：
- 电脑生成一次性配对二维码；
- 手机扫码，提交认证，需要设置该设备的独立密码；
- 电脑批准该设备；
- 手机浏览器保存长期设备凭据 Cookie，用于证明该浏览器已经获得电脑批准；
- 电脑只保存设备凭据哈希、设备密码哈希和设备资料，不保存 Cookie 中的明文秘密。

后续同一设备使用：
- 只需输入自己的设备密码，无需再次扫码或由电脑批准；
- 输入设备密码后保存会话 Cookie（10分钟无活动，再次访问需要重新输入设备密码）；
- 电脑可以查看、单独撤销已经批准的设备；
- 设备凭据长期有效，直到电脑撤销设备或手机清除浏览器 Cookie；
- 手机清除浏览器 Cookie 后需要重新配对，电脑端原设备记录仍可查看或删除。

补充：
- “10分钟无活动”只按点击、触摸、键盘等真实用户操作续期；WebSocket 心跳、自动请求和页面处于前台但静置均不续期；
- 设备列表显示“最后登录时间”，沿用成功输入设备密码时更新的 `lastLoginAt`，不追踪每次活动；
- 保留已有渐进锁定规则：设备密码第 5 / 10 / 15 / 20 次连续失败后，分别锁定 5 分钟 / 15 分钟 / 45 分钟 / 24 小时，成功登录后清零；公开登录和配对端点另有来源限速；
- Named Tunnel 暂不支持 CLI；CLI 保持通过 LAN / Quick 使用现有 PIN 认证；
- 配对码生成、批准、拒绝和撤销必须只能在电脑本机执行。不能依赖 `connection.isLoopback` 或 `rpc.handle(..., { authority: 'loopback' })`：当前 DSH 会忽略后者的第三参数，且 Pocket 会为远程页面改写 Host。实现采用独立 `/dsh-pocket-admin` 通道，并由代理在 Host 改写前拒绝所有非 loopback 请求；
- Named 模式仅允许配置中的固定 hostname 使用设备认证；其他公网 Host 直接返回 403，禁止回落到 Quick 共享 PIN，避免 alternate-Host 认证降级。

## 关键决策与理由（改动前必读，防止回退）

> 本节记录已拍板的决策和「为什么不做另一个方案」。修改认证、代理、RPC、隧道行为之前先读本节。
> 每条决策都有对应的守护测试——**删测试等于删决策**：要改行为，先改这节文档并说明理由，再动代码。

### 架构与安全边界

1. **不整体合入旧分支 `feat/secure-passkey-access`**（37 文件 +3083/−5791）：它会删除 CLI、把代理改听 127.0.0.1、把隧道固定为 named，回退 upstream v2.10.2/2.10.3 的全部安全修复。只裁剪复用 `lib/device-auth.mjs`、认证页面、`client/auth-entry.js` 构建、测试骨架。
2. **设备管理必须走独立 `/dsh-pocket-admin` RPC 通道，并由代理在 `loopbackAuthority()` 改写 Host 之前拦截**。原因（都不束能绕过）：
   - DSH 的 `connection.rpc.handle(channel, handler)` 只收两个参数，第三参数 `{ authority: 'loopback' }` 被**静默忽略**（见 dsh-client-connection `lib/index.js` 的 handle 实现），不能作为权限依据；
   - Pocket 注入脚本会把远程页面的 `connection.isLoopback` 强制为 `true`，不能用；
   - 代理会把远程请求的 Host/Origin/Referer/Sec-Fetch-Site 改写成 loopback 权威，DSH 侧看到的永远是"本机"。
   - 所以唯一可靠边界 = `policyHost()`（TCP 源地址兜底、只收紧不放松）在改写前判定 `classifyHost(host) !== 'loopback'` 即 403。守护测试：`test/secure-proxy.test.js`「管理 RPC 在 Host 改写前拒绝所有非本机通道」。
3. **普通 `/dsh-pocket` 通道保留并仅拒绝 `device.*` 端点**（web-rpc 内双重防御）：因为移动端 `fileRead`（issue #17 复制文件能力）等既有功能走这个通道，整段拦截会破坏 LAN/Quick 现有能力。
4. **`connection.isLoopback` 补丁保留**（`lib/proxy.mjs` 的 remote settings patch）——它只是远程 UI 能力开关，**永远不能当权限依据**。

### 通道与认证语义

5. **Named 模式仅精确匹配配置的固定 hostname 启用设备认证；其他公网 Host 一律 403，禁止回落到共享 PIN**（fail closed）。否则同一代理入口换个 Host 就从设备认证降级到 8 位 PIN（alternate-Host 降级）。HTTP 与 WebSocket 两条入口共用同一 `publicChannelForHost` 判定。守护测试：`test/secure-proxy.test.js` 三通道判定用例。
6. **Named 暂不支持 CLI**：CLI 无法走二维码/本机批准/浏览器 Cookie 流程。CLI 继续通过 LAN/Quick 用 PIN（`bin/dsh-pocket.mjs` 原样保留，其默认认证是 upstream #90 修复的一部分，不许删）。
7. **LAN/Quick 保持共享密码，不做设备认证**：浏览器无法拿到可靠设备标识，且 LAN IP 变化、Quick 域名每次变新后，原域名的设备 Cookie 不可迁移，设备认证体验不稳定（原始设计依据，见上文目标形态）。
8. **「10 分钟无活动」只按真实用户操作续期**（pointerdown/keydown/touchstart，15s 节流上报 `/pocket-auth/activity`）。不是 keepalive、不是页面可见性：旧分支的 SESSION_GUARD_SCRIPT「页面可见每 30s ping」会让前台静置永不超时，已废弃。WebSocket 心跳不算活动；会话过期后既有 WS 连接由代理定时校验并主动断开。守护测试：`test/device-auth.test.js`「只有真实活动接口续期」。
9. **设备列表显示「最后登录时间」（lastLoginAt）**，不做"最后活动时间"：每次活动写盘代价大、含义模糊；成功登录时更新一次即可（2026-09-03 拍板）。守护测试：「设备列表字段明确为 lastLoginAt」。
10. **保留渐进锁定与来源限速**：设备密码第 5/10/15/20 次连续失败分别锁 5 分钟/15 分钟/45 分钟/24 小时，成功登录清零；登录 30 次/分、配对 10 次/5 分按来源限速。**不信任 `x-forwarded-for`**（upstream 同样不信）；`cf-connecting-ip` 仅在 Cloudflare 回连场景有意义。守护测试：`test/device-auth.test.js` 锁定/限速用例。
11. **凭据 + 密码双条件**：未配对浏览器即使知道设备密码也不能登录；登录成功轮换设备 token（旧 token 立即失效）；状态文件只存哈希（sha256 tokenHash + Argon2id 密码哈希，m=19456/t=2/p=1，`argon2` 锁定 0.45.1 保证各平台预编译二进制）。守护测试：「设备凭据与密码必须同时成立」。
12. **配对约束**：一次性 token（5 分钟、用过即焚）、同一时间只允许一个待批准申请（新申请在旧申请处理前会被拒）、提交配对后手机可关闭页面、批准不自动发凭据（凭据在提交时已发、批准只是入册）。守护测试：「配对 token 单次使用，同一时间拒绝第二个待批准申请」。
13. **不提供设备密码修改/找回**：忘记密码 = 电脑撤销设备 → 重新配对（2026-09-01 拍板）。

### 通道行为

14. **Quick 不随 DSH 重启自动恢复，只有 Named 自动恢复**：Quick 域名重启后必然变新，自动恢复等于替用户重新做「把电脑暴露到公网」的决定（PIN 还可能轮换）；Named 地址固定才适合常驻。`tunnel-auto.json` 记录开启时的通道，`restoreTunnelIfNeeded` 仅在 `mode === 'named'` 时拉起；手动关闭公网清除标记（两种通道都一样）。守护测试：`test/service.test.js`「Named 重启后自动拉起；Quick 只记录标记」。
15. **三通道安全声明分文案**（2026-09-03 拍板，同日二次修订）：通用声明以「链接+密码」为模型，对 Named（无共享 PIN）不成立。LAN 讲同网段可尝试访问 + **HTTP 明文可被监听**；Quick 讲链接+PIN 模型 + Cloudflare 临时域名回收/复用风险；Named 讲长期入口可扫描 + 设备凭据管理/撤销 + Tunnel Token 保管 + 防爆破。二次修订要点：三份开启声明统一补后果等级句（执行任意命令 = 交出电脑）与「开关状态跨 DSH 重启保持」；Quick 风险方向修正为「你拿到的链接可能被别人用过并留下旧访客」（域名被回收分给你之后，旧访客顺着旧记录访问到的是**你的**隧道；你关闭后域名分给别人则与你的安全无关）；Named 补浏览器账号云同步/公用设备凭据风险，删除丢失场景做不到的「清理 Cookie」指令；**局域网免密独立声明**：关闭「局域网访问密码」时单独弹窗勾选确认，不并入 LAN 开启声明。LAN 开启声明中「无弹窗时机」的缺口由决策 19（LAN 默认关闭）消除。守护：`test/locales.test.js`（zh/en key 对齐）。
16. **设置页三区块 + `tunnelActiveMode`**：界面按**实际运行中**的通道显示二维码与启停态，而不是按配置模式——配置可以在隧道运行期间被改，显示配置会误导。守护测试：`test/smoke.test.js` 可选链守卫等。

18. **本方案文档是说明 PR 改动的重要文件，随 PR 进入上游仓库**：文档提交放在链尾（当前挂在 `feat/lan-default-off`，即堆叠链的最后一个 PR）。`AGENTS.md` 是 AI 协作工作规则，不进上游 PR；改文档时同样遵守「docs 提交放在代码提交之后」的顺序约定。
19. **LAN 默认关闭（已拍板，独立 PR `feat/lan-default-off` 实现）**：插件安装后 LAN 默认关，必须手动开启至少一次（开启时必读声明），三通道语义就此完全统一（默认关、手动开、开启见声明）。扫码即用不受影响——二维码本来就只在通道开启后才存在，开启这一步正是强制过目声明的时机；CLI 同样可一键启动。两个已接受的代价：① 缺省语义翻转（`lanEnabled !== false` → `=== true`）会让从未动过开关的老用户升级后 LAN 静默关闭，作为 breaking change 在发布说明标注，**不引入一次性迁移标记**（避免永久复杂度）；② 「开箱即用」是上游卖点，此改动单独提 PR 并给出完整理由；如上游对默认值有不同意见，按其反馈再行讨论。
